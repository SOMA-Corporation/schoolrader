# 고교 종합분석 리포트 — 분석리포트 섹션 작업설명서

참고자료가 아니라 작업 규칙서. §5 순서를 건너뛰고 바로 제작 시작 금지.

> **학교급 분기** — 이 문서의 **§0 절대 규칙 · §4 틀 규격 · §8 빌드 · §9 원자료 함정**은
> 초·중·고 공통이다. 반면 **§2 페이지 지도(21쪽)와 §3 자료 매핑은 고등학교 전용**이다.
> 초등·중학교는 절 구성이 다르다 — `분석리포트_작업설명서_초.md` · `_중.md` 를 따른다.
> 왜 그렇게 갈랐는지는 `초중등_리포트_설계개요.md` 에 실측과 함께 적어 두었다.

만드는 것: 입시학원 내부용 고교 분석 리포트(표지~07절, 최대 21쪽). 독자는 학원 상담교사(표지 “내부용” 표기 유지). 공시 데이터·학교 규정을 상담 실무 판단 근거로 번역하는 문서 — 각 절 말미 ▸ 분석 노트가 핵심 가치다. 단순 요약이 아니다.

틀은 만들지 않는다. 복사한다. 「종합보고서」 폴더의 분석리포트_휘문고_전체html(예시) 가 틀의 정본이다. 이 HTML을 받아서 행과 숫자만 대상 학교 데이터로 갈아끼운다. CSS·클래스·표 열 구성·페이지 배치는 손대지 않는다.

산출물: 분석리포트_{학교명 약칭}.pdf 한 개 → 「종합보고서」 폴더(§8). 08 대학진학 절은 이 문서 소관이 아니다 — 「대학진학 섹션 작업설명서」가 이 PDF 뒤에 붙인다.

## 0. 절대 규칙

1. 틀은 템플릿 HTML이 정본. <style> 블록, 클래스 이름, 표의 열 구성, 페이지 배치를 변경 금지. “더 예쁘게”도, “행이 많아서 지면이 부족해서”도 위반.

1. 템플릿을 안 열고 시작 금지. 예시 PDF를 눈으로 보고 틀을 추정하는 방식은 금지한다. HTML 소스를 연다.

1. 예시와 다르게 가야 할 사정이 생기면 — 만들기 전에 멈추고 사용자에게 묻는다. 만든 뒤에 통보하는 것은 위반. (과거 실패: 06-2~06-4의 3개년 막대 구조를 임의로 집계 막대 1개로 바꾸고 보고하지 않음.)

1. 없는 데이터는 만들지 않는다. 보간·추정·타교 수치 대입 금지. 없으면 절을 빼거나 추정임을 명시.

1. 폼 2개 먼저. ①자료 충족도 QnA(§6) → ②목차 체크박스(§7) 확인 후 제작.

1. 절 임의 증감 금지. 포함 여부는 §7 체크 결과만 따른다.

1. 금지: 데이터 없는 절을 “일반적으로는…”으로 채우기 / 예시의 휘문고 수치·문장 잔존 / 추정치를 실측처럼 표기 / 출처 없는 수치.

## 1. 폴더 구조 (컬렉션 「올커니」)

```text
올커니/
├ 가이드라인/                    ← 사람용 세팅 절차서 (「가이드라인」 노트)
├ 분석리포트 섹션 작업설명서 (노트) ← 이 문서
├ 대학진학 섹션 작업설명서 (노트)
├ 종합보고서/
│  ├ 분석리포트_휘문고_전체html(예시) ★ 틀 정본 — 여기서 시작한다
│  ├ 분석리포트_휘문고_전체(예시)   ← 위 HTML의 렌더 결과 PDF (대조용)
│  ├ 분석리포트_휘문고_발췌(예시)
│  └ 분석리포트_{학교}.pdf        ← 산출물을 여기에 넣는다
├ 데이터_{학교}/                  ← 작업 대상 입력
│  ├ Data (노트)                 ← 스쿨레이더 OpenAPI 수집 결과
│  ├ 학업성적관리규정 (.hwp / .pdf)
│  ├ 동아리활동현황.xls
│  ├ 학교교육과정편성운영평가.hwp  ← 05절 학점배당표
│  └ 교과별학업성취사항.xls × 3개년
└ 스쿨레이더 (링크)
```

입력은 데이터_○○고, 출력은 「종합보고서」. 완성 PDF를 데이터_ 폴더에 두지 않는다.

세팅(데이터_○○고 폴더)이 없으면 §5-0 분기 절차로 폴더·Data 노트부터 만든다. 사람용 세팅 절차서는 「가이드라인」 참고.

### 4-2. .ach — 06-2 ~ 06-4 표 구조 (이 절이 가장 자주 틀린다)

열은 5개로 고정:

```text
분류(7%) | 과목(14%) | 학기(6.5%) | 3개년 분포 (위→아래 2023 · 2024 · 2025)(53.5%) | 판정·분석(19%)
```

- 분류 — td.grp, rowspan으로 기초 / 탐구 / 예체능·기타 묶음

- 과목 — td.subj. 학기 연속 과목은 공통국어1·2처럼 한 행에 병기하고, 아래 줄에 회색 소형 글씨로 구 과목명(舊 국어)을 붙인다. rowspan으로 1·2학기를 묶는다

- 학기 — td.sem, 1학기 / 2학기

- 3개년 분포 — 셀 하나에 .yline 3줄. 각 줄은 <span class="yr">23</span> + <div class="bar"> (A~E 5개 <i class="sA…sE" style="width:N%">) + <span class="ann">μ81.9 · A 20.9</span> 해당 연도 데이터가 없으면 그 줄은 막대 없이 – 만 둔다

- 판정·분석 — rowspan으로 과목 단위. 6.8pt. 한 과목의 3년치를 한 줄로 판정한 라벨을 적는다. 문제 있는 과목은 .red 판정 라벨

예 (휘문고 정본에서): A 21→45→31% — 연도 변동 큼 / 3년 내내 A 최험 — 구조적 관문 / 하위(D+E) 두께 전과목 최대 / 중간 수준 유지 / 관대화 추세 / A 후함 — 부담 낮음 / 3단계 산출 · 무부담 / 소인수·E 집중 — 선택 재고 / 무부담 트랙 (A 92%) / 하위 이탈 관리 대상 / 수능형 — 하위 집중 지속 / 진로선택 3단계

### 4-3. 06절 색 규칙

- 과목명 — 청색 = A 75% 이상(대부분 석차등급 미산출), 적색 = 최근 기준 A 12% 이하 또는 E 30% 이상

- 수치 — 청색 = 평균 90 이상 · A 75% 이상 / 적색 = 평균 60 이하 · A 12% 이하 · E 30% 이상 / 황색 = D 20% 이상

- 범례 ■ A ■ B ■ C ■ D ■ E 를 06절 각 면 상단에 반복

### 4-4. 06-6 등급컷 역산

- 방식: 표준편차 정규근사 (1등급 10% · 2등급 34% · 3등급 66% · 4등급 90% 지점)

- 컷이 100점을 넘으면 “만점권”으로 표기한다. 100 초과 값이 나온다고 방식을 바꾸지 않는다

- 열: 학년 | 과목 | 평균 | 표준편차 | 1등급컷 | 2등급컷 | 3등급컷 | 4등급컷 | 참고: 舊9등급 1컷

- 색: 황색 표준편차 = 20 이상(분산 큰 과목) · 청색 1등급컷 = 분산이 커서 만점 없이도 1등급 진입 여지가 큰 과목

- 각주에 “특정 연도 실제 컷을 보증하지 않는 상담용 감각 자료” 유지

### 4-5. 표지·출처

- 상단 라벨 SCHOOL RESEARCH · 입시학원 내부용 + 우측 공시연도 · 작성일

- 영문 헤더 → 학교명 h1 → table.meta 2열 → 목차 박스 → 출처 각주

- 출처 각주: 원자료 전부 나열 + 환산치·추정치 명시 + 대외 배포 시 원자료 확인 요망 유지

## 5-0. 세팅 — 시작 분기 (환경별)

리포트 요청이 들어오면 §5 제작 순서로 바로 가지 않는다. 먼저 아래를 순서대로 밟는다.

공통 (환경 무관)

1. 대상 학교를 묻는다. 학교명이 대화에 이미 있으면 생략.

## 5. 작업 순서

1. 템플릿 확보 — 「종합보고서」의 분석리포트_휘문고_전체html(예시)를 내려받아 HTML 소스를 연다. .pg 개수와 §2 지도가 일치하는지 확인.

1. 인벤토리 — 대상 데이터_○○고 폴더의 파일을 열어서 확인(§9의 함정 점검 포함). 확인 항목: 학업성취 xls 몇 개년(파일 안의 학년도로) / 표준편차 컬럼이 있는 연도 / 동아리 xls에 부서별 전수 유무 / 교육과정 첨부가 편제표가 맞는지 / 폴더명·규정·Data 노트의 학교가 전부 동일한지(다르면 즉시 확인받고 중단).

1. QnA 폼 A 제시(§6) → 멈추고 응답 대기.

1. 목차 체크 확인(§7). 표시 없으면 질문.

1. 데이터 주입 — 템플릿의 .pg를 순서대로 돌며 행과 숫자만 교체. §2 지도의 쪽 배치를 유지한다. 자료가 없어 빼는 쪽은 그 .pg를 통째로 제거하고, 표지 목차의 쪽번호를 다시 매긴다.

1. 렌더 — §8.

1. 구조 대조 검수 — §8-4. 수치 검산만으로 끝내지 않는다.

1. 업로드 — 「종합보고서」에 분석리포트_○○고.pdf.

## 8. 빌드 파이프라인

산출물은 PDF 한 개: 분석리포트_{학교명 약칭}.pdf (예: 분석리포트_단대부고.pdf). 약칭은 학교 이름을 줄인 것(단국대학교사범대학부속고등학교 → 단대부고). 애매하면 정식 학교명을 그대로 쓴다.

8-1. 템플릿 복사 — 내려받은 HTML을 스크래치 폴더에 report.html로 복사. <style> 블록은 한 글자도 고치지 않는다.

8-2. 데이터 주입 — .pg 단위로 본문만 교체. 표 열 구성·클래스·rowspan 패턴은 유지.

8-3. PDF 변환 (Windows)

```text
chrome --headless=new --disable-gpu --no-pdf-header-footer \
  --virtual-time-budget=25000 --user-data-dir="<빈 폴더>" \
  --print-to-pdf="분석리포트_○○고.pdf" "file:///.../report.html"
```

- 웹폰트·렌더 대기 때문에 --virtual-time-budget 필수

- --user-data-dir을 매번 새 폴더로 준다. 재사용하면 이전 PDF가 그대로 남아 “고쳤는데 결과가 똑같은” 착시가 생긴다 (실제 발생함)

- macOS/Linux는 Chrome 동일 플래그. Edge(msedge)는 이 환경에서 출력 없이 조용히 실패한 사례가 있다 — Chrome을 먼저 쓴다

8-4. 검수 — 두 축을 모두 돌린다

*(가) 구조 대조* ← 이걸 빠뜨려서 사고가 났다

- 생성 PDF 쪽수 vs §2 지도 (뺀 절이 있으면 그만큼만 줄어야 한다)

- 쪽별 섹션 헤더 텍스트가 §2와 일치하는가

- .ach 표가 5열(분류·과목·학기·3개년 분포·판정·분석)로 유지되었는가

- 06-5·06-6이 18쪽에 함께 들어갔는가

- 표지 목차의 쪽번호가 실제 쪽과 맞는가

*(나) 내용 검수*

- 페이지 밖으로 넘친 요소 없음 (PyMuPDF로 각 쪽 최대 y좌표 확인)

- 모든 수치에 출처 / 추정치에 추정 표기

- 분석 노트가 데이터 재진술이 아니라 실무 결론인가

- 휘문고 수치·문장 잔존 0건 (텍스트에서 “휘문” 검색)

- 학교명·연도 전 페이지 일치

8-5. 업로드 — 「종합보고서」 폴더에. 3MB 내외라 Base64가 들어가지 않으므로 create_file_upload_url → 프리사인 URL에 PUT → complete_file_upload 순서로 올린다(save_file 아님). 원본 파일과 기존 리포트는 절대 덮어쓰지 않는다. 같은 이름이 이미 있으면 사용자에게 확인받는다.

8-6. 08 대학진학 절을 이어 붙일 거면 여기서 멈추고 「대학진학 섹션 작업설명서」로 넘긴다. 그 문서가 병합본을 따로 만든다(_진학추가 접미사).

## 9. 원자료 함정 · 규정 조항 번호

확장자를 믿지 마라 — 매직바이트로 판별한다.

| 앞 바이트 | 실제 형식 | 비고 |
| --- | --- | --- |
| 25 50 44 46 (%PDF) | PDF | .hwp로 내려오는 경우가 있다 (단대부고 학업성적관리규정) |
| D0 CF 11 E0 | OLE (진짜 HWP 5.0) | olefile + zlib.decompress(d, -15)로 BodyText/SectionN 추출, 태그 67이 문단 텍스트 |

표준편차 컬럼은 연도마다 있고 없다. 컬럼 개수(14 vs 16)로 판별하고, 없으면 06-6은 있는 연도로 돌린다.
